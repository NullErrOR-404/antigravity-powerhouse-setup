## 2. Technical Stack Invariants & Defaults
- **Stack Flexibility:** Never lock into one hardcoded stack. Always present 2–3 viable options comparing cost, speed, scale, and database tiering.
- **Database Selection Truths:**
  - For low-traffic / pay-as-you-scale client projects: Prefer serverless databases that **never pause on inactivity** (e.g. NeonDB for serverless Postgres, Cloudflare D1 / Turso for edge SQLite).
  - Supabase: Only recommend if the client needs all-in-one Auth + Realtime + Storage and is willing to pay the Pro tier or run an automated keep-alive.
- **Search & Discovery:** Every public client build must enforce SEO + GEO + AEO fundamentals (Semantic HTML5, JSON-LD Schema.org graphs for Perplexity/Google AI Overviews).
- **Frontend Standard:** Craft Floor rules enforced (quiet chrome, 4px grid, Tactile Spring Motion spring motion, one section per screen, no generic AI templates or emoji badges).
